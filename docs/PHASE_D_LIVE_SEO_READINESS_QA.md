## PHASE D-HOTFIX — Old Project URL Catch-All Cleanup

Date: 2026-05-19

### Issue Found

Phase D live QA found that `/projects/cyber-dashboard` and `/projects/secure-remote-work` returned HTTP 200 instead of 404.

### Root Cause

**There is no `app/projects/[slug]/page.tsx` catch-all route.** The 200 was caused by explicit redirect rules in both config files:

- `next.config.js` — had `{ source: '/projects/cyber-dashboard', destination: '/projects', permanent: true }` and same for `secure-remote-work`
- `vercel.json` — had the same two redirect rules

Both Vercel's CDN layer (vercel.json) and the Next.js layer (next.config.js) were redirecting these retired URLs to `/projects`, which returns 200. `Invoke-WebRequest` followed the redirect chain and reported the final 200.

### Fix Applied

Removed both redirect rules from both files:

**`next.config.js`** — removed:
```js
{ source: '/projects/cyber-dashboard', destination: '/projects', permanent: true },
{ source: '/projects/secure-remote-work', destination: '/projects', permanent: true },
```

**`vercel.json`** — cleared to `{}` (the only entries were the two retired project redirects).

Without redirect rules and without any matching route file, Next.js returns a natural 404 for these URLs.

### Files Changed

| File | Change |
|------|--------|
| `next.config.js` | Removed 2 redirect rules for retired project slugs |
| `vercel.json` | Cleared to `{}` — all entries were the retired redirects |
